feat(routing): Implementar arquitetura SSOT para URLs da aplicação

BREAKING CHANGE: URLs agora são gerenciadas através de hooks centralizados

## 🎯 Objetivo

Eliminar links hardcoded e estabelecer Single Source of Truth (SSOT) para
todas as URLs da aplicação, melhorando manutenibilidade, type-safety e
escalabilidade.

## ✅ Implementações

### Hooks SSOT Criados (5 hooks)

1. **useAppUrls** - Hook central para URLs globais
   - Profile (central, public, manage, edit)
   - Auth (login, register, onboarding)
   - Family (home, alerts, zones, settings)
   - Integração com hooks de módulos
   - 15+ URLs globais

2. **useServiceUrls** - URLs do módulo de serviços
   - Lista territorial dinâmica
   - Detalhes, criação e edição
   - Suporte a contexto geográfico

3. **useClassifiedUrls** - URLs do módulo de classificados
   - Lista territorial dinâmica
   - Detalhes, criação e edição
   - Suporte a contexto geográfico

4. **useBusinessUrls** - URLs do módulo de empresas
   - Lista territorial dinâmica
   - Portal, criação, edição e dashboard
   - Suporte a contexto geográfico

5. **useCommunityUrls** - URLs do módulo de comunidade
   - Feed e eventos territoriais
   - Grupos, recomendações e achados/perdidos
   - 12 URLs totais (territorial + global)

## 🏗️ Arquitetura

### Estrutura de Diretórios
```
src/
├── core/routing/hooks/
│   ├── useAppUrls.ts          # Hook central
│   └── index.ts               # Exports
└── modules/*/hooks/
    ├── useServiceUrls.ts      # URLs de serviços
    ├── useClassifiedUrls.ts   # URLs de classificados
    ├── useBusinessUrls.ts     # URLs de empresas
    └── useCommunityUrls.ts    # URLs de comunidade
```

### Padrão de Uso
```typescript
import { useAppUrls } from '@/core/routing/hooks';

function MyComponent() {
  const navigate = useNavigate();
  const appUrls = useAppUrls();
  
  // ✅ Correto - Type-safe, centralizado
  navigate(appUrls.services.list);
  navigate(appUrls.auth.login);
  
  // ❌ Errado - Hardcoded
  navigate('/servicos');
  navigate('/login');
}
```
